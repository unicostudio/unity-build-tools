# Build Tests

EditMode tests for the build module. Namespace `UnicoStudio.BuildSystem.Tests`.

Contents:
- `BuildArtifactNamingEditModeTests` — filename format + label sanitization.
- `BuildVersioningEditModeTests` — build-code / iOS build-number bump math.
- `BuildDefineResolverEditModeTests` — the editor-wide kind rule (Test adds globally, Release removes globally, config `ExtraDefines` stay player-only), `StripDefines` merging, sanitization, `ValidateConfig` findings, `HasDefine` exact-token matching. The two global buckets CAN be populated at once (a Test build adding its define while stripping a committed one) — an earlier bullet here claimed "never both at once", which the suite's own passing data contradicts; what is pinned is that the SAME define never lands in both and that the kind rule only feeds its define in the kind's direction. Three cases pin `ForbidInPlayer` as independent of the current globals: a strip entry absent from the globals is still forbidden, a Release build forbids the test define even when no global carries it (the exact iOS gap the old wiring shipped), and a Test build forbids strip entries but never its own define. `ConfigureDefinesStageEditModeTests` adds the composition case that drives `ApplyExtraDefines` from a real `Resolve` delta rather than a hand-built list — the hand-built lists are why the original wiring bug survived the suite.
  One `ValidateConfig` case feeds both lists a SINGLE-PASS sequence (values on the first enumeration,
  empty on every later one) and still expects the both-lists finding — that is what pins the
  materialize-before-use fix, since the method walks each list twice and the previous implementation
  lost the finding entirely on a lazy source.
- `BuildSystemSettingsEditModeTests` — `EffectiveTestModeDefine` fallback rules + `IsValidDefine` token grammar.
- `RemoteLoadRootEditModeTests` — the `RemoteLoadRoot` contract: `IsValidRemoteLoadRoot` accepts `http`/`https` in any casing (and around surrounding whitespace) and rejects null, blank, whitespace-only, a relative path (`ServerData/v`), a non-http scheme (`ftp://`), and an otherwise-valid https root behind a leading zero-width space — the last one is what pins the comparison as ORDINAL, since culture-sensitive prefix matching treats that character as ignorable and would accept a URL no CDN can serve. The ENDING is pinned as deliberately unconstrained, so a root not ending in `v` is still valid. A valid root reaches `EffectiveRemoteLoadRoot` trimmed (a trailing space would compose into a broken URL baked into the shipped catalog); a blank or malformed one is reported unusable (`null`) rather than degrading to a default, since there is no safe default to degrade to. `RequireRemoteLoadRoot` itself hard-calls `LoadOrNull` and so cannot be driven from a `CreateInstance` instance — `EffectiveRemoteLoadRoot` is the part it delegates to and the part pinned here. Instances are created in memory and destroyed in `[TearDown]`; the fixture never writes an asset.
- `ProfileBindingRuleEditModeTests` — the binding rule, both halves. `FindUnresolvedToken`: a surviving token is reported by its INNER TEXT (no class-name literal anywhere in the rule); a resolved token reports nothing; a multi-token value passes only when every token resolved and otherwise names the one that survived; a dotless token is not a false positive; a value with no tokens and an empty token (`[]`) both report nothing; an unbalanced raw value reports nothing AND leaves the bracket to the caller; an empty evaluated result reports nothing, pinning that callers must test emptiness themselves. `Inspect`: names a surviving token, reports `MalformedDelimiters` for the bracket case the token rule cannot see, reports `None` when every token resolved, prefers the TOKEN verdict when a value manages both problems, and reports `None` for an empty evaluated result.
- `RemotePathCheckEditModeTests` — `Evaluate`'s pure core: not requested is a `Pass`; an unresolved binding **Blocks** and names the token; malformed delimiters **Block** with their own distinct message; a value that resolves but is not a URL, and an empty evaluated value, both **Block**; a resolved URL passes and names the profile it actually checked.
- `DefinePlanCheckEditModeTests` — issue→severity mapping and the Pass-message define plan.
- `VersionFormatCheckEditModeTests` — semver `Pass` / `Block` cases.
- `TestModeConsistencyCheckEditModeTests` — define-vs-kind consistency severities.
- `ConfigPresenceCheckEditModeTests` — the config-discovery fallback made visible: zero configs Warn naming the Create-menu path (null list treated as empty), a present-but-no-match set Warns naming the requested platform/kind AND what exists (both partial matches pinned: same platform other kind, and same kind other platform), a match Passes naming the resolved asset, and null entries in the list are skipped, not matched or crashed on.
- `BuildConfigCatalogEditModeTests` — config lookup by platform+kind, plus `ResolveProfile`: a matching config's `Profile` wins, and with no matching config the kind fallback is `Test`→`Test` / `Release`→`Production`. Duplicate handling matches the sibling loaders: two configs for the same platform+kind log an error naming both and the FIRST wins (deterministic because `LoadAll` ordinal-sorts by path — that half is AssetDatabase integration and is pinned by reading, not by a unit test, per this file's `LoadAll` note).
- `BuildContextEditModeTests` — context accumulation behavior.
- `BuildPlatformExtensionsEditModeTests` — `BuildPlatform` → `BuildTarget` / `BuildTargetGroup` / `NamedBuildTarget` mappings.
- `AddressablesStageEditModeTests` — `FailureOf` null/error/clean result semantics.
- `PlayerBuildStageEditModeTests` — `OptionsFor` compression → `BuildOptions` mapping, and `SelectSymbolsArchives`, the pure core of the symbols-archive selection: a role-`"Symbols"` zip under the project root comes back project-relative ('/'-normalized), other roles are ignored even with "symbols" in their paths (the measured report carries raw `.so` and gradle entries exactly like that), a `"Symbols"` entry without the `.symbols.zip` suffix is skipped defensively, a path outside the root stays absolute, and multiple archives return in report order. The test inputs mirror the shape measured on the real 2026-08-07 AAB gate report.
- `OutputSelectionCheckEditModeTests` — no-output player build `Block` / valid output `Pass` cases.
- `StageSelectionCheckEditModeTests` — no-stage-selected `Block` / any-stage `Pass` cases.
- `CompressionCheckEditModeTests` — standard-LZ4HC `Pass` / deviation `Warn` / content-only-job `Pass` cases.
- `BuildResultEditModeTests` — JsonUtility round-trip contract for the SessionState-persisted result.
- `DevStateSnapshotEditModeTests` — JsonUtility round-trip contract for the reload/restart-crossing snapshot (incl. the legacy-payload skip guard).
- `ContentStateGuardEditModeTests` — 20 tests covering the whole guard. The `PlanRestore` decision table (moved here from the snapshot tests when the content state got its own owner); the EditorPrefs record's arm/disarm round-trip and its `\`→`/` normalization of BOTH stored paths; `Arm` rejecting every stamp no `Finish` could match (`0`, negative, `AnyJobStamp`) and writing no record when it does; `IsArmedFor` and `DisarmIfOwnedBy` treating a foreign record as an orphan to keep rather than this job's to discard. Then `Restore()` against the real file system: backup copied over a changed file, the byte-identical short-circuit that reports no rollback and leaves the mtime untouched, a file born during the run deleted both under `Assets/` and outside it (where the `.meta` goes too and `AssetDatabase` cannot act at all), a content directory `CleanPlayerContent` wiped recreated before the copy, the mismatched-stamp skip leaving file AND record untouched, `AnyJobStamp` applying a record armed by a different job, and the no-ops for an unarmed or path-less record. A corrupt payload written straight to the key pins that every read degrades instead of throwing — `IsArmedFor`, `ArmedPath` and `Restore` each warn once and erase the record, since `Finish`'s `finally` reads it upstream of `BuildJobState.Clear()` and `OrphanedDevStateRecovery`'s `[InitializeOnLoad]` constructor reads it before its `Disarm()` calls, where a throw wedges the job or the domain reload. The fixture saves whatever is under the shared production `EditorPrefs` key in `[SetUp]` and puts it back in `[TearDown]`, so it can never destroy a real in-flight build's rollback record.
- `CdnReminderCheckMessageEditModeTests` — `FolderFor` derives the staging folder from `UnicoBuildPaths.BUILD_PATH_BASE` instead of repeating it.
- `BuildStepRegistryEditModeTests` — splice positions, ordering determinism, positional anchors, materialize round-trip and failure modes (incl. a throwing constructor's root cause), every `RejectionReason` rule, and `Deduplicate` (via the hook-free internal core — test types never carry the attribute).
- `ConfigureDefinesStageEditModeTests` — `ApplyExtraDefines` merges into what PreBuild hooks already added, never duplicates, and evicts what the build strips; `NextGlobalDefines` composes the one global write (add + remove in a single string, order preserved, no duplicates, and an empty delta reproducing the current set so the caller can skip the write).
- `PostSuccessRunnerEditModeTests` — queue JSON round-trip, step execution with the deserialized result, per-step failure isolation, outcome attribution to the queue's own run, `Appended` surviving an unreadable payload, and `Claim` handing out one run at a time while persisting the rest (chained until the queue drains, nothing lost). The attribution pair SEEDS a stamped result under the production SessionState key (saved and restored around every test, with `UnicoBuildService`'s private cache reset on both sides so a seeded result can never shadow a real one): the matching-run case proves recording actually lands on the result, and the superseded-run case matches the one rejection message unique to a read-and-compared stamp — the prior single test matched "logged only", which all three rejection branches emit, and passed with attribution entirely disabled (measured).
- `UnicoBuildServicePostStepEditModeTests` — `ShouldRecordPostStep`: a draining queue's outcomes land on their own run's result, never on a newer one, and an unstamped queue is only logged. Also `AppendArtifactTo`, the pure core of `AppendPostArtifact`: it appends to `Artifacts` AND `TypedArtifacts` keeping them index-aligned, and pads a legacy result whose typed list is shorter than its path list before appending — without the padding every reader after the gap would pair one artifact's kind with another artifact's path. A third case pins `ArtifactKind`'s integer values, so a member inserted rather than appended fails loudly instead of silently re-mapping kinds persisted by `JsonUtility`. The stateful wrapper itself is deliberately NOT driven here: it reads and writes the production `SessionState` result key, which a test run must never disturb.
- `TestModeDefineRenameCheckEditModeTests` — default name passes; renamed-and-default-gone passes; a rename (or one-underscore typo) with the default still committed warns and names every platform that carries it.
- `PreflightGateEditModeTests` — `PreflightRunner.Gate` policy behavior: Interactive warns never
  block; Strict blocks non-exempt Warn; Strict still lets a strict-exempt Warn through while
  recording it; a `Block` wins even when a later entry would also warn; the first blocking
  message wins in registration order; `CdnReminderCheck`, `ConfigPresenceCheck` and
  `TestModeConsistencyCheck` are the only `IsStrictExempt` checks (the guard test pins the
  exact set so a new opt-out is a deliberate, reviewed act).
- `UnicoBuildCliParseEditModeTests` — CLI flag parsing: a full release invocation maps every
  field, Unity's own args (`-batchmode`, `-projectPath`, ...) are ignored, the CI default is no
  bump unless flagged, `-buildCode` pins the value and disables `-bumpBuildCode` regardless of
  flag order, missing `-platform`/`-kind` and bad enum/missing-value tokens are reported as
  errors, and boolean-value flags parse correctly.
- `CiCompletionWatcherEditModeTests` — `Decide`'s pure decision core: a running job waits before
  the deadline, the deadline times out even while still running, a successful conclusion waits
  for the PostSuccess queue to drain before exiting 0, a failed conclusion exits 1, and an
  unstarted/no-result job waits until the deadline.

Rules:
- These are fast, pure-logic EditMode tests — no real builds, no domain reloads, no device.
- Run with `tests-run testMode=EditMode testNamespace=UnicoStudio.BuildSystem.Tests`. Note: the full-project EditMode suite can exceed the MCP CLI's 60s HTTP cap; the `UnicoStudio.BuildSystem.Tests` namespace filter still compiles the whole editor assembly and runs every build test.
- New build logic that can be exercised without opening a build should get a test here; reload-resume, real Addressables content, and device builds stay human-validated via the panel.
