# Build Support

Small, mostly-pure helpers used by the stages. Easy to unit-test in isolation.

Contents:
- `BuildArtifactNaming` — builds the output filename `{ProductPrefix}[_Label]_v{version}({code})_{dd.MM.yyyy}_{TEST|RELEASE}.{ext}` and sanitizes labels to `[A-Za-z0-9]`. Pure math except `ProductPrefix`, derived from the host game's `Application.productName` (spaces/punctuation stripped).
- `BuildDefineResolver` — decides, for a build kind + the current global defines + the config's `ExtraDefines`/`StripDefines` + the project's test-mode define name, which defines to add player-only (`AddViaExtra`), add globally (`AddToGlobal`), remove globally (`RemoveFromGlobal`), or keep out of the player list entirely (`ForbidInPlayer`). The last two are NOT the same set: `RemoveFromGlobal` is strip ∩ current globals — it drives the one global write — while `ForbidInPlayer` (strip plus the test define on non-Test builds) deliberately ignores the current globals, because whether a define happens to be committed for a platform says nothing about whether the player may carry it. `ConfigureDefinesStage` evicts hook-added defines with `ForbidInPlayer`; wiring `RemoveFromGlobal` there instead was a real shipped bug — the eviction no-oped exactly on platforms whose globals never carried the define, i.e. exactly when the hook's copy was the one that would ship. The test-mode define obeys ONLY the kind rule — config entries naming it are dropped (and reported by `ValidateConfig`, whose findings `DefinePlanCheck` maps to Warn/Block). Also owns `HasDefine(rawDefines, define)` — the exact-token membership check every presence probe must use (a raw `Contains` would false-positive on e.g. `MY_TEST_MODE`).
- `BuildVersioning` — `NextAndroidCode` / `NextIosBuildNumber` (both `+1`). The single source of the bump math.
- `ProfileBindingRule` — whether the bindings written directly in an Addressables profile value actually resolved. The evaluator does NOT throw or return empty when a binding fails: it substitutes the token's own text with the delimiters stripped, so `"[A.B]"` becomes `"A.B"` and a garbage path is baked into the catalog silently. THE RULE IS DERIVED FROM THE RAW TOKEN, NOT A NAME LITERAL — it asks whether a `[...]` token's inner text survived into the evaluated string, so it needs no class name. The guard it replaced tested the evaluated value for one host game's class name as a string literal — something a shared package must not know, and something that stopped being true the moment the binding surface moved into the package. (`ProfileBindingRule.cs` keeps a note naming that literal, deliberately: it is the one place the history is worth recording.) `Inspect(raw, evaluated)` is the whole rule and returns a verdict of `None` / `UnresolvedToken` (with the surviving token's inner text) / `MalformedDelimiters`. `FindUnresolvedToken` alone is NOT the rule: a well-formed token that fails to resolve loses its brackets, so a surviving `[` or `]` can only mean the raw value's own delimiters are unbalanced — a second, distinct problem with a different fix that no token extraction can see. The token verdict wins when a value manages both, because it names the binding that broke. `RemotePathCheck` and `AddressablesStage` both take their verdict from `Inspect`, so preflight can never pass a value the build then rejects; only the wording is local to each.
- `DevStateSnapshot` — captures and restores the editor state a build mutates: scripting defines, `buildAppBundle`, Android `DebugSymbols.level`, and the active Addressables profile id. The `Platform` field is the build request's TARGET platform, used only as the `NamedBuildTarget` key for the defines round-trip — `Restore()` never switches the active platform back, so after a platform-switching build the editor stays on the build target. Also captures the pre-build versions (bundleVersion, build code, addressables VERSION_NO); `RestoreVersions()` rolls those back ONLY on failure — success keeps the bumps, since they then describe a real, produced build. Profile capture/restore is gated by `UNICO_HAS_ADDRESSABLES`; all fields stay unconditional (SessionState/EditorPrefs payload stability). The Addressables content-state file is NOT part of this snapshot — its path is owned by Addressables and only resolvable after the platform and profile switches, so it lives in `ContentStateGuard` (Editor/Core).

Rules:
- Prefer pure, deterministic functions here — anything with no editor side effects should be testable without opening a build.
- `DevStateSnapshot` is `[Serializable]` and round-tripped through `JsonUtility` (embedded in `BuildJobState`), so its members are public FIELDS.
- The test-mode define name comes from `BuildSystemSettings.ResolveTestModeDefine()` (default `TEST_MODE`), never a bare string literal; presence checks on a raw defines string must go through `BuildDefineResolver.HasDefine`.
- The kind rule is EDITOR-WIDE, in both directions: Test builds resolve the test-mode define into `AddToGlobal`, Release builds into `RemoveFromGlobal`. Both mutate global defines (→ domain reload) and both are undone by the `DevStateSnapshot` restore. The reason is not symmetry for its own sake: editor assemblies compile with the ACTIVE BUILD TARGET's global defines, so a player-only add (`extraScriptingDefines`) leaves every editor-side build participant — build callbacks, host steps, the Addressables content build — compiled for the opposite kind. Config `ExtraDefines` stay in `AddViaExtra` (player-only) by contract; they describe the player, not the build's intent.
- The global add and every global removal share ONE `SetScriptingDefineSymbols` call, so a build pays at most one reload here — and none at all when the target's defines already match the requested kind.
- `DevStateSnapshot` uses the Unity 6 `UnityEditor.Android.UserBuildSettings.DebugSymbols.level` API (not the deprecated `EditorUserBuildSettings.androidCreateSymbols`).
- A `None` verdict from `ProfileBindingRule` is NOT proof that evaluation succeeded: an empty evaluated string contains neither a token's text nor a bracket. Every caller must test emptiness itself — both do.
