# Build Pre-flight Checks

`IPreflightCheck` implementations run before a build. Results render as HelpBoxes in the panel; a `Block` stops the Build click with a "Cannot build" dialog and aborts `UnicoBuildService.Start`.

Contents (registration order in `PreflightRunner.Default`):
- `StageSelectionCheck` — **Block** when neither Build Addressables nor Build Player is selected (the job would bump versions and finish "OK" producing nothing). The panel also disables the Build button for this case.
- `AddressablesAvailabilityCheck` — **Block** when `BuildAddressables` is requested without com.unity.addressables installed.
- `RemotePathCheck` — **Block** when the build's Addressables profile has a `Remote.LoadPath` that does not resolve (verdict from `ProfileBindingRule.Inspect`: an unresolved binding and malformed `[`/`]` delimiters get their own messages), or that resolves to something that is empty or not a URL. Pass when the Addressables stage is not requested. Registered IMMEDIATELY AFTER `AddressablesAvailabilityCheck`, deliberately: `PreflightRunner.Gate` reports the FIRST blocking message, and "the package is not installed" is the clearer one when both would fire. It reads `ctx.Profile` — the BUILD's profile, never the active one, since preflight must not switch anything — which is why every caller resolves the profile before running checks. The body is gated by `#if UNICO_HAS_ADDRESSABLES`, with a `Pass` in the `#else`. It reads through Addressables' domain-lifetime property cache and deliberately does NOT clear it (`Run` executes on every panel repaint; clearing there would throw away the caching for the whole editor session). The cost is that a Pass here can be optimistically stale — `AddressablesStage` clears the cache itself and re-validates before anything is written, so a stale Pass costs a late failure, never a bad catalog.
- `VersionFormatCheck` — **Block** unless the Version Name is strict semver `MAJOR.MINOR.PATCH`. Guards the value `ApplyVersionStage` writes to `bundleVersion`.
- `VersionDowngradeCheck` — **Warn** when the requested Version Name parses lower than the current `PlayerSettings.bundleVersion` (catches transposed digits that `VersionFormatCheck`'s shape check wouldn't); Pass when either version string fails to parse.
- `OutputSelectionCheck` — **Block** when a player build is requested with `OutputKind.None` (would finish "OK" with zero artifacts after burning the version bumps).
- `BundleIdCheck` — **Block** when the target's `BuildConfigCatalog` entry declares an `ExpectedBundleId` that doesn't match the actual application identifier; Pass when no expected id is configured for the target.
- `KeystoreCheck` — **Block** for Android Release player builds missing the custom keystore toggle, the keystore file, or the keystore/key-alias passwords; Pass for Test builds, non-Android platforms, or when Build Player is off. Its "passwords not set" block names the supported mechanisms (Player Settings, `UNICO_KEYSTORE_PASS` / `UNICO_KEYALIAS_PASS`, or a host-side editor injector) rather than any one host's script. ORDERING RULE this check makes concrete: preflight runs before every `[UnicoBuildStep]` anchor (`Start` gates on the checks before the pipeline is even materialized), so code that feeds state preflight READS — keystore passwords here — must run on editor load (`[InitializeOnLoad]`), never as a hook. The package's keystore sample shipped as a PreBuild hook for four versions and could never satisfy this check on the panel path; it is an on-load injector now (`Samples~/Hooks/Editor/KeystoreEnvInjection.cs`). The CLI path is unaffected either way: `UnicoBuildCli` injects before `Start` itself.
- `PlatformMatchCheck` — **Warn** when the active build target differs from the request (the build will switch platforms: slow reimport + reload).
- `UnityServicesCheck` — checks the Unity Services / project-id link. (Note: it can pass while offline/logged-out because the project id stays populated.) In batchmode the probe is blind (cloud init never runs), so it passes with a note — the panel remains the real guard.
- `CompressionCheck` — **Warn** when the requested compression deviates from the project-standard LZ4HC (Pass for content-only jobs). Checks the real `BuildRequest.Compression` that `PlayerBuildStage` maps to `BuildOptions` flags.
- `SplashLogoCheck` — flags the Unity splash logo being enabled.
- `TestModeConsistencyCheck` — verifies the current test-mode define (default `TEST_MODE`; renamable via `BuildSystemSettings`) matches the requested `BuildKind` (uses `BuildDefineResolver.HasDefine`). Its Warn is self-healing in both directions — `ConfigureDefinesStage` writes the kind rule into the global defines either way — which is why it is `IsStrictExempt`.
- `DefinePlanCheck` — surfaces the build's effective define plan (config `ExtraDefines`/`StripDefines` merged with the test-mode kind rule). **Block** on config-authoring errors (invalid tokens, a define in both lists); **Warn** when a config lists the kind-ruled define (the entry is ignored); Pass shows the exact `+build-only` / `+global (restored)` / `-global (restored)` delta.
- `TestModeDefineRenameCheck` — **Warn** when `BuildSystemSettings` renames the test define but the default `TEST_MODE` is still in some platform's global defines: the sign of a half-finished rename (or a typo in the asset), where every other check resolves the same wrong symbol and passes while a Release can ship with test features compiled in. Pass when the name is the default or the default is gone everywhere.
- `BumpConsistencyCheck` — **Warn** when Bump Addressables Version is requested without Build Addressables (a successful run would keep the bump with no content produced).
- `CdnReminderCheck` — **Warn** on Release builds with Build Addressables selected, naming the versioned content output folder that still needs a manual CDN upload before shipping; Pass otherwise. The folder name comes from `CdnReminderCheck.FolderFor(version)`, which derives it from `UnicoBuildPaths.BUILD_PATH_BASE` so the reminder cannot drift from where the build actually stages content.

Rules:
- A check is a pure function of `BuildContext` → `CheckResult`; return `Pass` / `Warn` / `Block`, and never mutate project state.
- A check that reads `ctx.Profile` gets whatever the caller put there. `BuildContext.Profile`'s initialiser is `Test`, so EVERY caller must resolve the profile via `BuildConfigCatalog.ResolveProfile` BEFORE calling `PreflightRunner.Run` — the panel's display context as much as `UnicoBuildService.Start`. Both do.
- Only `Block` prevents a build. `Warn` is advisory — the panel surfaces it; `Start` does not stop on `Warn`.
- Register new checks in `PreflightRunner.Default()`.
- Keep messages actionable — they are shown verbatim to the developer in the panel.
- `IsStrictExempt` (defaults `false` on `IPreflightCheck`) marks a check whose `Warn` stays advisory even under `WarnPolicy.Strict` (CI's strict-warnings mode). `CdnReminderCheck` overrides it to `true` — CI runs its own CDN upload step, so that reminder must not make a strict Release build impossible. `TestModeConsistencyCheck` also overrides it to `true` — its Warn is self-healing (`ConfigureDefinesStage` applies the kind rule regardless), so it must not hard-fail a clean checkout where the test define is committed. Every other check blocks on Warn under Strict.
